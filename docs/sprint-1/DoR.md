# Definition of Ready (DoR) — Sprint 1

## MedShift

A Definition of Ready (DoR) define os critérios que uma User Story deve atender
antes de ser considerada pronta para entrar em desenvolvimento durante a Sprint.

Uma User Story somente será considerada pronta quando atender aos critérios abaixo.

---

## Critérios do DoR

- [ ] A User Story possui uma descrição clara e compreensível.

- [ ] A User Story segue o formato:

  **Como [tipo de usuário], quero [necessidade], para [benefício].**

- [ ] A prioridade da User Story está definida no Product Backlog.

- [ ] O valor de negócio da User Story está identificado.

- [ ] Os critérios de aceitação estão definidos.

- [ ] As regras de negócio relacionadas à User Story estão identificadas.

- [ ] Existe pelo menos um cenário válido previsto para testar a funcionalidade.

- [ ] Existe pelo menos um cenário inválido previsto, quando aplicável.

- [ ] As dúvidas importantes sobre a User Story foram esclarecidas com o Product Owner
e, quando necessário, com o cliente/P2.

- [ ] As dependências com outras User Stories ou tarefas foram identificadas.

- [ ] A equipe entende qual problema a User Story pretende resolver.

- [ ] A funcionalidade pode ser demonstrada no VisuAlg sem necessidade de alterar
o código durante a apresentação.

- [ ] A User Story foi dividida em tarefas de desenvolvimento.

- [ ] As tarefas possuem tamanho adequado, com duração prevista inferior a 8 horas.

- [ ] A equipe considera a User Story viável para ser desenvolvida dentro da Sprint.

---

## Regra da Equipe

Uma User Story somente poderá entrar em desenvolvimento quando atender aos
critérios definidos neste DoR.

Caso algum critério importante ainda não seja atendido, a User Story deverá
ser esclarecida ou ajustada antes do início do desenvolvimento.

---

## Verificação do DoR

A verificação do DoR será realizada durante a Sprint Planning com a participação de:

- Product Owner;
- Scrum Master;
- Desenvolvedores.

O Product Owner será responsável por esclarecer a necessidade e os critérios
de aceitação da User Story.

O Scrum Master auxiliará na organização e divisão das tarefas.

Os Desenvolvedores avaliarão a viabilidade técnica e participarão da estimativa
das tarefas.
