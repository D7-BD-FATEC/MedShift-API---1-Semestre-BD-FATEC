# Definition of Done (DoD) — Sprint 1

## MedShift

A Definition of Done (DoD) define os critérios que uma User Story deve atender
para ser considerada concluída pela equipe.

Uma User Story somente será considerada finalizada quando atender aos critérios
aplicáveis definidos abaixo.

---

## Critérios do DoD

- [ ] A funcionalidade foi implementada no VisuAlg.

- [ ] O algoritmo executa corretamente.

- [ ] Todos os critérios de aceitação da User Story foram atendidos.

- [ ] As regras de negócio relacionadas à funcionalidade foram respeitadas.

- [ ] A funcionalidade foi testada em pelo menos um cenário válido.

- [ ] A funcionalidade foi testada em pelo menos um cenário inválido, quando aplicável.

- [ ] Entradas inválidas previstas nos critérios de aceitação são tratadas corretamente.

- [ ] As mensagens apresentadas ao usuário são claras e permitem entender o resultado.

- [ ] A funcionalidade pode ser demonstrada no VisuAlg sem necessidade de alterar
o código durante a apresentação.

- [ ] O código foi versionado no GitHub.

- [ ] Os commits relacionados à funcionalidade seguem o padrão definido pela equipe.

- [ ] A documentação relacionada à User Story foi atualizada, quando necessário.

- [ ] Os cenários de teste utilizados foram registrados.

- [ ] A funcionalidade está integrada ao incremento da Sprint.

- [ ] A equipe consegue explicar o funcionamento da solução desenvolvida.

- [ ] A funcionalidade está pronta para ser apresentada na Sprint Review.

---

## Regra da Equipe

Uma User Story não será considerada concluída apenas porque o código foi escrito.

Para ser considerada concluída, a funcionalidade deverá:

- Executar corretamente;
- Atender aos critérios de aceitação;
- Respeitar as regras de negócio;
- Ter sido testada;
- Estar versionada no GitHub;
- Estar pronta para demonstração.

Caso algum critério importante ainda não seja atendido, a User Story não deverá
ser marcada como concluída.

---

## Verificação antes da Sprint Review

Antes da Sprint Review, a equipe deverá confirmar que:

- [ ] As User Stories marcadas como concluídas atendem ao DoD;
- [ ] O incremento executa no VisuAlg;
- [ ] Os cenários de sucesso foram testados;
- [ ] Os cenários de falha foram testados;
- [ ] Os dados necessários para a demonstração estão preparados;
- [ ] O Product Owner sabe informar quais itens foram concluídos;
- [ ] O Product Owner sabe informar quais itens não foram concluídos e o motivo;
- [ ] A equipe consegue explicar as principais decisões tomadas no algoritmo.

---

## Responsáveis pela verificação

A verificação do DoD será responsabilidade de toda a equipe:

- **Product Owner:** verifica se a funcionalidade atende à necessidade e aos critérios de aceitação;
- **Scrum Master:** verifica se o processo e a Definition of Done estão sendo respeitados;
- **Desenvolvedores:** testam, validam e garantem o funcionamento técnico da funcionalidade.
